# Exposr

A self-hosted reverse tunnel in the spirit of [rathole](https://github.com/rapiz1/rathole), with
an admin web UI and MongoDB-backed configuration. You can expose TCP and UDP services that sit behind NAT
or a firewall through a public server, and manage everything from a browser, with no config files and no restarts.

```
 visitor ──► server:20005 ──┐                       ┌──► 127.0.0.1:25565 (your service)
                            │   TLS (port 2333)     │
                  exposr-server ◄──────────────── exposr-client
                    │    ▲                     (behind NAT)
            MongoDB ┘    └── admin UI / GraphQL (port 8080)
```

- **Server** (`crates/server`): the tunnel engine, a GraphQL API (axum + async-graphql), and the static admin UI.
- **Client** (`crates/client`): runs next to your services. It needs only the server address, a token, and the
  certificate fingerprint. Which services it forwards, and where, comes from the server and updates live.
- **Protocol** (`crates/proto`): everything runs over TLS (rustls). The client keeps one control connection open, opens one
  stream per TCP visitor, and opens one stream per UDP service carrying the datagrams.
- **Admin UI** (`web/`): Vike + React + daisyUI + i18next (EN/FR) + motion, prerendered to static files.

## Deploy on Coolify

1. Push this repository to a Git provider that Coolify can reach.
2. In Coolify, go to **New resource → Docker Compose** (from your repository) and select `docker-compose.yml`.
3. Set these environment variables in the resource:
   - `PUBLIC_HOST`: the hostname or IP clients will connect to, e.g. `exposr.example.com`.
     Its DNS must point at the server itself (not through a CDN proxy).
   - `SERVICE_PORT_RANGE` (optional, default `20000-20099`): the public ports your services may use.
   - `SERVICE_PASSWORD_MONGO` and `SERVICE_PASSWORD_ADMIN` are generated by Coolify.
4. Give the `exposr` service a domain. `SERVICE_FQDN_EXPOSR_8080` is pre-filled, and Coolify serves the admin UI over HTTPS.
5. Open the ports in your server firewall: **2333/tcp** plus the **service range in both TCP and UDP**.
6. Deploy, then sign in as `admin` with the password stored in `SERVICE_PASSWORD_ADMIN`.

Notes:
- The admin UI goes through Coolify's proxy, but port 2333 and the service ports are published directly by Docker.
  Traefik never touches tunnel traffic.
- The tunnel TLS certificate is self-signed and generated on first start in the `exposr-data` volume. Clients
  **pin its SHA-256 fingerprint**, which is shown in the UI, so no CA is needed. Keep the volume, or the fingerprint changes.
  To use your own certificate instead, set `TLS_CERT` and `TLS_KEY`. Clients then use `--ca` or the public roots.
- Docker only forwards the ports it publishes, so the server refuses services outside `SERVICE_PORT_RANGE`.
  A very large range slows down container start. A few hundred ports is fine.

## Connect a client

In the UI, go to **Clients → New client**. The ready-to-copy commands, including the token, are shown once:

```sh
# Docker (multi-arch image published by CI: amd64 + arm64)
docker run -d --name exposr-client --restart unless-stopped --network host \
  -e EXPOSR_SERVER=exposr.example.com:2333 \
  -e EXPOSR_TOKEN=<token> \
  -e EXPOSR_FINGERPRINT=<sha256> \
  ghcr.io/gallifree/exposr-client

# or the binary
exposr-client --server exposr.example.com:2333 --token <token> --fingerprint <sha256>
```

Then go to **Services → New service**: pick the client, the protocol, a public port, and the local address as seen
from the client (e.g. `127.0.0.1:25565`). The port opens immediately and the client starts forwarding.

## Docker images

GitHub Actions (`.github/workflows/docker.yml`) builds `linux/amd64` and `linux/arm64` images on every push to `main`
and on `v*` tags:

- `ghcr.io/gallifree/exposr`: the server (UI included)
- `ghcr.io/gallifree/exposr-client`: the client

Tags: `latest` and `sha-<commit>` from `main`, and `1.2.3` / `1.2` from a `v1.2.3` tag. Pull requests build without pushing.

## Configuration (server)

| Variable | Default | |
|---|---|---|
| `MONGODB_URI` | `mongodb://localhost:27017` | A standalone instance is fine (no replica set needed) |
| `MONGODB_DB` | `exposr` | |
| `CONTROL_ADDR` | `0.0.0.0:2333` | Where clients connect (TLS) |
| `ADMIN_ADDR` | `0.0.0.0:8080` | Admin UI + `/api/graphql` (plain HTTP; put a TLS proxy in front) |
| `SERVICE_BIND_IP` | `0.0.0.0` | Address the public service ports bind on |
| `SERVICE_PORT_RANGE` | none | e.g. `20000-20099`; restricts allowed public ports |
| `PUBLIC_HOST` | none | Hostname shown in the client commands |
| `DATA_DIR` | `./data` | Holds the generated certificate |
| `TLS_CERT` / `TLS_KEY` | none | PEM files to use instead of the self-signed certificate |
| `WEB_DIR` | `./web/dist/client` | Built admin UI |
| `ALLOW_REGISTRATION` | `false` | Enables `POST /api/register` (see below) |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / random | First account, created only if there are no users. A random password is printed in the logs |

Client: `EXPOSR_SERVER`, `EXPOSR_TOKEN`, `EXPOSR_FINGERPRINT`, or `EXPOSR_CA` (PEM file), and `EXPOSR_SERVER_NAME`.

## HTTP tunnels and self-registration

An `http` service has no public port. Requests to `https://<admin domain>/t/<secret>/<path>` are forwarded
to `/<path>` on the client's local address, through the admin listener (and so through Coolify's TLS).
Only the SHA-256 of the secret is stored, so the URL itself is the credential.

With `ALLOW_REGISTRATION=true`, anyone can create such a tunnel without an admin. The Rustart launcher uses
this to expose its MCP server:

```sh
curl -X POST https://t.example.com/api/register -H 'Content-Type: application/json' -d '{}'
# {"server":"t.example.com:2333","fingerprint":"…","token":"…","path":"/t/<secret>"}
```

The new client gets one `http` service forwarding to `127.0.0.1:8765`. Sending `{"token":"…"}` instead
issues a new secret for that client (the old URL stops working). New registrations are limited to 30 per hour.

## How configuration reaches the engine

MongoDB is the source of truth. After every change made from the UI, the server reloads the configuration and
reconciles live:
- ports open and close
- moved services are re-bound
- disabled clients are disconnected
- clients get their new service list

A resync also runs every 30 s. It picks up edits made directly in the database and retries ports that failed to bind,
for example because they were already in use.

Traffic counters are kept in memory and saved to MongoDB every 10 s. Activity events are kept for 30 days
(TTL index).

## Development

```sh
# MongoDB
docker run -d --name mongo -p 27017:27017 mongo:8.0

# server (API on :8080, tunnel on :2333)
cargo run -p exposr-server -- --admin-password admin1234 --public-host localhost

# UI with hot reload on :3000, proxies /api to :8080
cd web && npm install && npm run dev

# tests: end-to-end TCP + UDP through a real server and client, no MongoDB needed
cargo test --workspace
```

After changing the API, run `cargo run -p exposr-server -- --print-schema > web/schema.graphql` to update the
schema file.
